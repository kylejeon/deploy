# 디자인 명세 — AutoDeploy MVP (Slack UX)

- **작성자**: @designer
- **작성일**: 2026-05-21
- **버전**: v0.1 (초안)
- **연결된 개발지시서**: [docs/specs/dev-spec-autodeploy-mvp-20260521.md](dev-spec-autodeploy-mvp-20260521.md) v0.4
- **대상 플랫폼**: Slack (Bot, Socket Mode). 데스크탑·모바일·웹 모두 동일 렌더링 가정

---

## 1. 디자인 원칙

AutoDeploy의 UI는 Slack 메시지가 전부다. 디자인 결정의 우선순위:

1. **정보의 명확성 > 예쁨**. 새벽에 호출되어 자고 일어난 운영자가 한눈에 상태를 파악할 수 있어야 한다.
2. **실패는 빠르게, 명확하게**. 성공 메시지보다 실패·재현 정보를 더 잘 보이게.
3. **채널 소음 최소화**. 진행 상황은 **스레드 안에서** 갱신, 채널 본문은 작업 1개당 메시지 1개.
4. **메시지 폭주 금지**. 스크립트 stdout은 **단일 메시지를 `chat.update`** 로 갱신, 매 라인마다 새 메시지 발송하지 않음.
5. **흑백·축소·캡처에서도 의미 보존**. 색상에만 의존하지 말 것 (실패는 이모지 + 색 + 단어 "실패" 셋 다).
6. **명령 응답은 즉시**. 비동기 작업이라도 5초 이내 "받았다" 응답 보장.

## 2. 메시지 인벤토리

봇이 만들어내는 모든 메시지 유형. 각각의 트리거·렌더링 채널 위치를 명시.

| # | 메시지 | 트리거 | 위치 |
|---|--------|--------|------|
| M-1 | **작업 시작 부모 메시지** | `install` 명령 수락 | 채널 본문 |
| M-2 | **작업 시작 ack** (즉시 응답) | `install` 명령 수락 | M-1의 스레드 |
| M-3 | **단계 시작/완료 알림** | 각 단계 진입·완료 | M-1의 스레드 |
| M-4 | **stdout 라이브 미리보기** | 스크립트 실행 중 5초마다 | M-1의 스레드 (1개 메시지 `chat.update`) |
| M-5 | **작업 성공 완료** | 모든 단계 통과 | M-1의 스레드 + M-1 메시지 갱신 |
| M-6 | **작업 실패** | 단계 실패 | M-1의 스레드 + M-1 메시지 갱신 |
| M-7 | **작업 취소** | `cancel` 수락 후 단계 경계에서 중단 | M-1의 스레드 + M-1 메시지 갱신 |
| M-8 | **status 응답** | `status [job-id]` | 채널 본문 (ephemeral 검토) |
| M-9 | **list 응답** | `list [N]` | 채널 본문 (ephemeral) |
| M-10 | **help 응답** | `help` 또는 미지의 명령 | ephemeral |
| M-11 | **권한 거부** | 화이트리스트 외 사용자 명령 | ephemeral |
| M-12 | **검증 에러** (인자 누락·알 수 없는 type 등) | 명령 파싱 실패 | ephemeral |
| M-13 | **봇 부팅/재연결 알림** (선택) | 데몬 시작·Socket 재연결 | 채널 본문 (1회) |

> **ephemeral**: 명령을 친 사용자에게만 보이는 메시지 (`response_url` 또는 `chat.postEphemeral`). 채널 소음을 줄이려면 status/list/help는 ephemeral 권장.

## 3. 메시지별 명세

각 메시지의 텍스트 와이어프레임 + Block Kit 구조 + 상태별 변형.

### M-1. 작업 시작 부모 메시지 (채널 본문)

```
┌─────────────────────────────────────────────────────────┐
│ 🔵  AutoDeploy 작업 #42 시작                              │
│                                                          │
│ 대상         192.168.1.50                                │
│ 유형         hybrid-with-ai                              │
│ 병원         HOSP01 · 서울대병원                          │
│ 요청자       @yonghyuk                                    │
│ 시작         16:23:11                                    │
│                                                          │
│ 진행 상황은 이 스레드에서 갱신됩니다 ↓                    │
└─────────────────────────────────────────────────────────┘
```

**Block Kit 구조**:
```
header              "🔵  AutoDeploy 작업 #42 시작"
section.fields      [ "대상\n*192.168.1.50*",
                      "유형\n*hybrid-with-ai*",
                      "병원\n*HOSP01 · 서울대병원*",
                      "요청자\n<@U01ABC>",
                      "시작\n*16:23:11*" ]
context             "진행 상황은 이 스레드에서 갱신됩니다 ↓"
```

**상태 변형** (작업 종료 시 M-1 자체를 `chat.update`로 갱신):

| 상태 | 헤더 아이콘 | 헤더 텍스트 |
|------|-----------|------------|
| running (초기) | 🔵 | AutoDeploy 작업 #42 시작 |
| succeeded | ✅ | AutoDeploy 작업 #42 완료 (4분 12초) |
| failed | ❌ | AutoDeploy 작업 #42 실패 — *app_install* |
| cancelled | ⚠️ | AutoDeploy 작업 #42 취소됨 |

### M-2. 작업 시작 ack (스레드 첫 메시지)

```
┌─────────────────────────────────────────────────────────┐
│ ⏳  접수했습니다. 작업 ID #42                              │
│      취소: @autodeploy cancel 42                          │
└─────────────────────────────────────────────────────────┘
```

5초 이내 응답 보장 (AC-1).

---

### M-3. 단계 시작/완료 알림 (스레드)

단계 시작 메시지 (각 단계마다 1개):

```
┌──────────────────────────────────────────────┐
│ ⏳  [단계 3/5] 인프라 설치 시작 (infra_install) │
│ 16:24:02                                      │
└──────────────────────────────────────────────┘
```

단계 완료 메시지 (성공 시, 진행률 누적):

```
┌──────────────────────────────────────────────┐
│ ✓  [단계 3/5] 인프라 설치 완료 (1분 38초)       │
└──────────────────────────────────────────────┘
```

**단계별 이모지**:
| 단계 | 이모지 | 한글 표시 |
|------|-------|----------|
| ssh_connect | 🔌 | SSH 접속 |
| git_pull | 📥 | 스크립트 동기화 |
| infra_install | ⚙️ | 인프라 설치 |
| app_install | 📦 | 어플리케이션 설치 |
| healthcheck | 🩺 | 헬스체크 |

> 단계 번호(N/5)는 deployment_type에 무관하게 항상 5단계 (ssh→git→infra→app→health).

---

### M-4. stdout 라이브 미리보기 (스레드, 단일 메시지 갱신)

스크립트 실행 중 한 메시지를 `chat.update`로 5초마다 갱신. 마지막 10줄만 표시 (라인 80자 제한, 더 길면 `… (truncated)`).

```
┌─────────────────────────────────────────────────────────────┐
│ 📋  실시간 로그 — infra_install                              │
│ ```                                                          │
│ [16:24:15] Installing dependencies...                       │
│ [16:24:18] apt-get update OK                                │
│ [16:24:22] docker installed                                 │
│ [16:24:28] containerd configured                            │
│ [16:24:31] kubelet starting...                              │
│ [16:24:34] kubelet ready                                    │
│ [16:24:37] pulling registry images                          │
│ [16:24:42] image pull progress: 4/12                        │
│ [16:24:48] image pull progress: 9/12                        │
│ [16:24:55] image pull progress: 12/12 — done                │
│ ```                                                          │
│ 마지막 업데이트 16:24:55 · 5초 간격                          │
└─────────────────────────────────────────────────────────────┘
```

**갱신 규칙**:
- 단계 시작 시 새 미리보기 메시지 1개 생성
- 5초 간격 `chat.update` (Slack rate limit 1req/sec/channel 안에서 안전)
- 단계 종료 시 미리보기 메시지를 더 이상 갱신하지 않고 마지막 상태 그대로 둠 (다음 단계는 새 M-4 생성)
- 라인이 80자 초과면 `…` 으로 잘라 표시. DB에는 전체 저장

### M-8. status 응답 (ephemeral)

진행 중 작업이 있을 때:
```
┌────────────────────────────────────────────────────────────┐
│ ℹ️  현재 작업                                                │
│                                                             │
│ ID #43 · 192.168.1.51 · hybrid-without-ai                  │
│ 현재 단계      📦 app_install (2/5 완료, 3/5 진행 중)        │
│ 경과 시간      2분 47초                                       │
│ 시작           16:30:12                                      │
│ 요청자         @engineer1                                     │
│                                                             │
│ 전체 진행 보기: <스레드 링크>                                  │
└────────────────────────────────────────────────────────────┘
```

진행 중 작업이 없을 때:
```
┌────────────────────────────────────────────────────────────┐
│ ℹ️  진행 중인 작업이 없습니다.                                 │
│ 최근 작업 보기: @autodeploy list 5                            │
└────────────────────────────────────────────────────────────┘
```

`status <job-id>` 형태로 특정 작업 조회 시 동일 레이아웃 + 종료된 작업이면 상태(성공/실패/취소) + 종료시각 표시.

```
┌────────────────────────────────────────────────────────────┐

> "관리자가 누구"인지 채널 핀에 명시되어 있다고 가정. 봇은 사용자를 노출하지 않음 (보안).

이벤트 로깅: `job_events`에 `level=warn, message="unauthorized_command: <user_id>"` 기록.

### M-12. 검증 에러 (ephemeral)

여러 케이스의 통합 패턴:

**`--type` 누락**:
```
⚠️ install 명령에 --type이 필요합니다.

올바른 형식:
@autodeploy install 192.168.1.50 --type=hybrid-with-ai --code=HOSP01

유효 TYPE:
  • on-premise
  • hybrid-with-ai
  • hybrid-without-ai
```

**알 수 없는 type**:
```
⚠️ 알 수 없는 type: "hybrid-magic"

유효 TYPE:
  • on-premise
  • hybrid-with-ai
  • hybrid-without-ai
```

**`--code` 누락**:
```
⚠️ install 명령에 --code (병원코드)가 필요합니다.
```

**같은 IP에 동시 install**:
```
⚠️ 192.168.1.50에 이미 진행 중인 작업이 있습니다: #43
상태 보기: @autodeploy status 43
```

**Bitbucket 인증 실패** (작업 시작은 했으나 git_pull에서 실패):
M-6 변형. stderr 영역에 다음 메시지 + 권장 조치:
```
권장 조치:
  • Bitbucket App Password 만료/회수 확인
  • 새 토큰 발급 후 .env의 BITBUCKET_APP_PASSWORD 갱신
  • 데몬 재시작
```

```
┌────────────────────────────────────────────────────────────┐

재연결의 경우는 운영자가 알 필요 없으므로 소음 방지를 위해 게시하지 않음 (로그 파일에만).

## 4. 컴포넌트 / 재사용 패턴

| 컴포넌트 | 어디에 쓰이나 | 정의 |
|---------|--------------|------|
| **JobHeader** | M-1, M-3, M-5, M-6, M-7 | 상태 아이콘 + "작업 #N <서술>" + (선택) 단계 라벨 |
| **JobFields** | M-1, M-8 | 대상/유형/병원/요청자/시작 시각 2열 fields |
| **CodeBlockTail** | M-4, M-6 | 모노스페이스 코드블록 + 마지막 N줄 잘라내기 헬퍼 |

단계 이모지: §3 M-3 표

### 타이포 / 포맷
- **헤더**: Block Kit `header` 블록 (Slack이 결정한 크기. 별도 토큰 없음)
- **본문 강조**: `*bold*`
- **인라인 코드**: `` `code` ``
- **블록 코드**: ` ``` ... ``` ` (모노스페이스, 들여쓰기 보존)
- **숫자/시간 표기**: 한국식 — "4분 12초", "16:24:55" (24h). 날짜는 "2026-05-21"
- **사용자 멘션**: `<@U01ABC>` (이름 추출은 Slack이 자동)
- **언어**: 한국어 우선, 기술용어(SSH, kubectl, docker, image 등)는 영문 그대로

### 간격
- 한 메시지 안에서 논리 그룹은 **divider** 또는 **빈 줄**
- 필드 그룹은 2열 (`section.fields`로 자동 정렬)
- 코드블록 위·아래에 컨텍스트 한 줄 (제목 또는 "마지막 업데이트 시각")

## 6. 접근성

Slack의 접근성 기본을 따르고, 추가 보강:

- **색 의존 금지**: 실패는 ❌ + "실패" 단어 + 빨간 바 셋 다. 한두 가지가 없어도 의미 전달
- **모노스페이스 영역은 짧게**: 코드블록은 단일 화면에서 스크롤 없이 보이도록 (M-4는 10줄로 잘라 표시, 전체는 DB)
- **스크린 리더**: Block Kit는 기본 alt 텍스트 지원. 이모지 외에 항상 텍스트 라벨 같이 표기
- **모바일**: Slack 모바일은 attachment·field 자동 1열. 컬럼이 많은 표(M-9)는 5열 이하 유지
- **고대비**: 색상 토큰은 Slack 기본값 활용 — 별도 커스텀 색 (낮은 대비) 안 만듦

---

## 7. 반응형

- **데스크탑 vs 모바일**: Slack이 자동 처리. 우리는 컬럼 수와 라인 길이만 신경 쓰면 됨
- **라인 폭**: 본문 행은 80자 이내 권장 (모바일 줄바꿈 보존)
- **표 (M-9)**: 5열 이하, 각 셀 12자 이내. 길면 truncate + 툴팁 대신 다음 행에 보조 정보
- **이미지/첨부**: v1에서는 사용 안 함 (Slack은 텍스트만으로 충분히 표현 가능)
