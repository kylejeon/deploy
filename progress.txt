install은 create_job(slack_thread_ts=None) → notifier 호출(객체에만 세팅) 순서라

## 2026-05-26 (later 4) — sudo 비밀번호 자동 주입 (stdin)

### 배경
앞 패치 직후 #7 작업이 `sudo: a terminal is required to read the password`로
실패. connecteve 계정이 NOPASSWD가 아니라 sudo가 비밀번호를 요구했고, 봇은
비대화형 SSH라 입력 불가. 그런데 .env에 이미 SSH_PASSWORD가 있고 sudo도
같은 계정 비밀번호를 쓰니, 그걸 stdin으로 흘려넣으면 됨.

### 구현 (176/176 통과)
- scripts.py `_sudo_prefix(password)` 도입.
  - 비밀번호 없으면 `sudo` (기존 동작 유지, NOPASSWD 환경)
  - 비밀번호 있으면 `printf '%s\n' '<pw>' | sudo -S -p ''` (stdin 주입)
  - `printf`는 bash 빌트인이라 별도 프로세스 안 생김 → ps에 비밀번호 노출 X
  - shlex.quote로 특수문자(#$) 안전
- run_script에 `sudo_password: str = ""` param 추가
- workflow.install_missing_tools에 동일 패턴 적용 (apt-get update + install을

## 2026-05-26 (later 5) — debconf 비대화형 강제

### 배경
sudo 비밀번호 패치 후 #9 작업이 인프라 설치(3/5)에서 exit 100으로 실패.
stderr 마지막 줄:
  debconf: 프론트엔드를 초기화할 수 없음: Dialog
  debconf: 이 프론트엔드는 제어 TTY를 필요로 합니다.

원인: setup-site.sh가 내부에서 apt install을 호출 → apt가 패키지 설정
충돌·서비스 재시작 확인 등을 debconf로 물으려 함 → 비대화형 SSH에 TTY가
없어 Dialog/Readline 둘 다 실패 → exit 100.

우리 직접 apt-get(자동 git 설치)엔 DEBIAN_FRONTEND=noninteractive 박혀있었지만,
스크립트 내부 apt 호출은 환경변수를 안 물려받음.

### 구현 (176/176 통과)
- scripts.py: 모든 스크립트 호출을 `env DEBIAN_FRONTEND=noninteractive`로 감쌈.
  - sudo: `<sudo prefix> env DEBIAN_FRONTEND=noninteractive ./script ...`
  - non-sudo: `env DEBIAN_FRONTEND=noninteractive ./script ...`
  - 핵심: `env`가 자식 프로세스 환경에 변수를 박아넣어 sudo·apt 체인을 지나도 유지
- test_scripts: 기존 단언 "sudo ./setup-onpremise.sh" → "sudo" + "./setup-onpremise.sh" + "DEBIAN_FRONTEND=noninteractive" 분리
