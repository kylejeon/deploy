install은 create_job(slack_thread_ts=None) → notifier 호출(객체에만 세팅) 순서라

## 2026-05-26 (later 4) — sudo 비밀번호 자동 주입 (stdin)

### 배경
앞 패치 직후 #7 작업이 `sudo: a terminal is required to read the password`로
실패. connecteve 계정이 NOPASSWD가 아니라 sudo가 비밀번호를 요구했고, 봇은
비대화형 SSH라 입력 불가. 그런데 .env에 이미 SSH_PASSWORD가 있고 sudo도
같은 계정 비밀번호를 쓰니, 그걸 stdin으로 흘려넣으면 됨.

### 구현 (176/176 통과)
- scripts.py `_sudo_prefix(password)` 도입.
  - 비밀번호 없으면 `sudo` (기존 동작 유지, NOPASSWD 환경)
  - 비밀번호 있으면 `printf '%s\n' '<pw>' | sudo -S -p ''` (stdin 주입)
  - `printf`는 bash 빌트인이라 별도 프로세스 안 생김 → ps에 비밀번호 노출 X
  - shlex.quote로 특수문자(#$) 안전
- run_script에 `sudo_password: str = ""` param 추가
- workflow.install_missing_tools에 동일 패턴 적용 (apt-get update + install을

### 증상

tilde expansion은 **단일 인용 안에서 동작하지 않아**서 `~`가 literal로 처리됨.
→ 봇이 `git clone ... '~/gateway-infra-next'`로 호출하면 진짜로 `~`라는
이름의 폴더가 홈 디렉토리에 생기고 그 안에 clone됨.

### 픽스 (181/181 통과)

  로드 시점에 `~/foo` → `/home/<ssh_user>/foo`로 치환. 이후 모든 코드가
  절대경로만 다루게 됨. shlex.quote로 감싸도 안전.
- 신규 테스트 3건:
  - test_work_dir_tilde_expanded_to_remote_home

### 운영 후속 (타겟 서버 정리)
잘못 생성된 literal `~` 폴더는 사용자가 한 번 정리해야 함:

## 2026-06-01 (오후) — site_register 단계 확장: hybrid도 자동 등록

### 무엇을 했나 (221/221 통과)

### 동작 매트릭스
| deployment_type | base URL | Host 헤더 | 비고 |

| hybrid-without-ai | 위와 동일 | 위와 동일 | installationType 다름 |

## 2026-06-01 (저녁) — register 명령어 추가: 6단계만 단독 재실행

### 무엇을 했나 (232/232 통과)
`@autodeploy register <job-id>` 명령어 신설. 기존 작업의 hospital 데이터로
site_register API만 다시 호출. SSH/스크립트/healthcheck 같은 무거운 단계는
일절 건드리지 않음. 작업 #23처럼 hybrid가 옛 코드로 설치돼 자동 등록이 빠진
케이스를 손쉽게 보완하는 용도.

### 동작
1. `@autodeploy register 23` 받으면 DB에서 Job 로드
2. ephemeral ack 즉시 응답 (백그라운드 처리 알림)
3. workflow.register_existing_job(job)을 백그라운드 task로 실행
4. 성공/실패 결과를 원본 작업의 슬랙 스레드(있으면)에 chat_postMessage로 게시
5. DB에는 'job_events.site_register: 수동 재시도' 한 줄 기록 (jobs.status는 안 건드림)

### on-premise vs hybrid
- hybrid: cfg.site_cloud_base_url (https://dev-gateway.connecteve.com) 사용. 별도 정보 불필요.
- on-premise: job.extra_urls["Frontend"] 우선, 없으면 job.admin_web_url에서 포트 파싱.
  admin_web_url이 'http://IP/' 형태(설치 시 Frontend URL 못 잡은 케이스)면 명확한 에러.
